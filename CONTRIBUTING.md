# Участие в проекте

Спасибо за интерес к ResumeMaker. Проект ранний, поэтому особенно полезны небольшие,
хорошо проверенные изменения, а не большие переписывания.

## Перед началом

1. Прочитайте [`AGENTS.md`](AGENTS.md) и правила затронутого компонента в [`agents/`](agents/).
2. Для существенных изменений сначала откройте issue: обсудите контракт и границы.
3. Не добавляйте реальные персональные данные, ключи, токены и ссылки на приватные сервисы.

## Окружение

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
cp .env.example .env
```

Тесты требуют PostgreSQL с правом `CREATEDB`. Подробности — в [README](README.md#тесты).

## Что проверить перед pull request

```bash
python -m ruff check .
python -m pytest
```

Для миграций дополнительно:

```bash
alembic upgrade head
alembic check          # не должно быть незакоммиченных изменений схемы
alembic downgrade base
alembic upgrade head
```

## Правила изменений

### Архитектура

- Исходные ответы кандидата — источник истины. Производные данные должны пересобираться.
- Нельзя придумывать факты, даты, компании, метрики и контакты. Неизвестное — это `null`
  и warning, а не догадка.
- JSON-профиль — версионируемый контракт со строгой валидацией, а не свободный ответ LLM.
- Рендеринг PDF — детерминированный код. LLM не участвует в вёрстке.
- Внутренние кредиты и balance tokens провайдера — разные единицы.
- Списание и создание job выполняются атомарно; повторные вызовы идемпотентны.

### Код

- Python 3.11+, аннотации типов, `from __future__ import annotations`.
- Стиль — `ruff` (`pyproject.toml`), длина строки 100.
- Публичные функции и модули получают короткий docstring на английском.
- Секреты — только через environment/secret manager.
- Логи и сообщения об ошибках не содержат prompt целиком и PII.

### Тесты

- Новое поведение сопровождается тестами; багфикс — воспроизводящим тестом.
- Состояния, идемпотентность и негативные сценарии важнее «счастливого пути».
- Fixtures и golden-файлы — только синтетические данные.
- Для Ledger/платежей нужны тесты на повторную доставку и конкурентный доступ.

### Контракты и версии

Изменение схемы профиля, цен, шаблонов или renderer — это версионируемое изменение.
Старые профили не перезаписываются без миграции или новой версии.

## Стиль коммитов и PR

Используются Conventional Commits:

```text
feat(ledger): reject overdraft under concurrent debits
fix(api): resolve session dependency from the app state
docs(readme): document the disposable test cluster
test(payments): cover duplicate webhook delivery
chore(ci): add PostgreSQL service
```

В PR опишите: что изменилось, зачем, какие инварианты затронуты и как это проверено.
Один PR — одна логическая тема.

## Релизы

Версия и история изменений ведутся в [`CHANGELOG.md`](CHANGELOG.md).
Изменение цен, схемы или PDF-шаблонов требует отдельной записи и, при необходимости,
миграции данных.
